# Python MCTS Phase 2 — Information-Set Search Consumer

## Context

The TypeScript search-simulation foundation (Phase 1 in `aplhago-mcts.md`) is implemented and validated:
`POST /api/rl/search/start|replay|close` (token `x-rl-control-token`, schema `tfm.rl-search.v1`), served from
`terraforming-mars/src/server/training/SearchSimulationService.ts` + `src/server/routes/ApiRlSearch.ts`, contract
types in `src/common/models/RlSearchModel.ts`. Limits: 32 sessions, 60 s sliding TTL, 64 branches/batch,
32 steps/branch; `exact` mode never leaks another player's view (returns `boundary`), `determinized` mode
requires `RL_SEARCH_DETERMINIZATION_ENABLED=1`.

No Python consumer exists yet. The network already produces exactly what MCTS needs:
per-prompt legal-action priors + value + GRU recurrent state
(`TerraformingMarsNetwork` at `rl-environment/models/agent.py:566`, policy head :623, value head :655-663,
GRUCell :614, recurrent bookkeeping :1430-1465).

Goal of this phase: **policy-guided, root-player IS-MCTS over macro-actions, used for evaluation/play first.**
Learning from search (AlphaZero-style distillation into a replay buffer) is explicitly deferred — searched
actions are off-policy and must not enter the PPO rollout buffer.

## Architecture

```
RLAgent._make_move (models/agent.py:2311)
   └─ SearchPolicy.decide(...)          [new: rl-environment/search/]
        ├─ PositionEvaluator            priors/value/recurrent, no_grad, batched
        ├─ Lookahead / PUCT tree        macro-action branching at strategic roots
        └─ SearchClient                 aiohttp → /api/rl/search/* on game_instance.base_url
```

Key contract facts the Python side must honor:
- `observation` (start + `nextPrompt`) is a raw upstream-camelCase `PlayerViewModel`; run it through the same
  inbound normalization as `game_interface.py:478-479` (`tfm_schema`) before `StateEncoder.encode`, and apply
  `adapt_outbound_payment_schema` to `steps[].input` payloads (as `send_player_input` does at
  `game_interface.py:549-552`). The descriptors' `decoded_action` dicts are the same `InputResponse` JSON the
  live `/player/input` route accepts, so enumeration/decode is reused unchanged.
- `playerId` is the runtime `p<hex>` participant id — same id Python already uses for polling.
- Root eligibility on the server: Phase.ACTION, `activePlayer == playerId`, zero deferred actions, exactly one
  waiting prompt owned by the root, Stage-1 ruleset; otherwise structured errors
  (`unsupported_root`, `session_capacity`, …) → fall back to plain policy.
- Terminal results come as `terminal.players[]` with `rank`/`vp`; `boundary` (round/phase transition, discard
  recycle, other-player prompt in exact mode) has no observation — treat as a skipped sample.

## New module: `rl-environment/search/`

1. **`config.py`** — `SearchConfig.from_env()` with defaults: disabled unless `ALPHAGO_SEARCH_ENABLED=1`;
   `top_k=8`, `determinizations=8`, `simulations_per_move=32`, `max_root_turns_depth=2`, `puct_c=1.5`,
   `leaf_batch=16`, `replay_timeout_sec=30`, `max_branches_per_batch=64` (enforced so `top_k × determinizations ≤ 64`).

2. **`simulator_client.py`** — async aiohttp client (`SearchClient`) for start/replay/close. Owns
   `x-rl-control-token` (reuse `RL_CONTROL_TOKEN`, same pattern as `game_interface.py:851,1299`), validates
   `schemaVersion == "tfm.rl-search.v1"`, maps error codes (`session_not_found`, `session_capacity`,
   `determinization_disabled`, `unsupported_root`, …) to typed exceptions, applies inbound/outbound schema
   adaptation, always closes sessions in `finally`, records per-batch latency counters for the throughput gate
   (64-branch ≥ 100 inputs/s target in `aplhago-mcts.md:39`).

3. **`evaluator.py`** — `PositionEvaluator` around the live `RLAgent` internals:
   - `evaluate(player_state, recurrent_by_player, player_id) -> (priors, value, descriptors, recurrent_out)`
     using `ActionDecoder.get_legal_action_descriptors` + `StateEncoder.encode` (on the inference executor,
     mirroring `_make_move:2326-2375`) + `_sync_forward_impl` under `torch.no_grad`.
   - `evaluate_batch(states, recurrent_in [B,128])` via `pad_bundle_batch` (`models/planner_common.py:255`) for
     leaf batches of 8-16.
   - Never touches `RLAgent._recurrent_hidden_by_player`; callers pass copied dicts. Each branch clones the
     recurrent state map up front (search of one decision must not corrupt live memory).

4. **`rollout.py`** — advances a branch from the root snapshot:
   - Branch state = action path (list of `{playerId, input}` steps) + per-branch recurrent map + determinization seed.
   - Loop: replay the grown path (server re-applies from the immutable root each call — O(path²) step
     applications, acceptable at depth 2-3); at each `nextPrompt`:
       - root player + top-level strategic prompt (`waitingFor.type == "or"`, ≥2 options) → stop, evaluate leaf.
       - any other prompt (root continuations, opponent prompts) → enumerate legal actions for that player's
         view, forward with that branch's recurrent state, sample (`torch.multinomial`, branch-local RNG seeded
         from `determinizationSeed`), append step.
       - `terminal` → compute root-perspective value from `terminal.players[]` via `scoring.calculate_v2_terminal_reward`.
       - `boundary`/`rejected` → mark sample invalid, drop from the mean.
   - Hard caps: 32 steps/path, `max_steps` guard against runaway continuations; opponents are driven by the
     searching network (self-play assumption), including in teacher-benchmark games.
   - Rollout requires `mode: "determinized"` (exact mode cannot return opponent views), so search needs
     `RL_SEARCH_DETERMINIZATION_ENABLED=1` on the servers; client checks the capability once and refuses to
     start with a clear log instead of per-branch `determinization_disabled` spam.

5. **`lookahead.py`** — Phase A (ships first, validates the whole loop):
   top-K first-step macro-actions (root priors) × D determinizations = one ≤64-branch replay batch per
   rollout step, roll each branch out to the root's next decision, choose the action with best mean value
   (argmax for benchmark, temperature option otherwise). Ties/unusable → plain policy sample.

6. **`node.py` + `mcts.py`** — Phase B (after Phase A lands): PUCT over root-turn macro-actions.
   `Node = {prior, visits, value_sum, children, action_path, continuation_path}`; score
   `Q + c·P·√N_total/(1+N)`; each simulation draws a fresh determinization seed, descends, reuses the node's
   cached continuation path (sampled at first visit), expands at the next root decision up to
   `max_root_turns_depth`, backs up the leaf/terminal value; a path that becomes `rejected` under a new
   determinization backs up the parent's current mean and truncates (documented v1 limitation).
   Returns the final visit distribution alongside the chosen action (future Phase-3 training target).

7. **`search_agent.py`** — `SearchPolicy.decide(agent, game_instance, player_id, player_state, filtered_descriptors) -> Optional[SearchDecision]`:
   prompt gate (or-type top-level, ≥2 distinct options, active player, not initialCards/payment/placement;
   forced prompts and routine prompts stay policy-only), session start, dispatch lookahead or PUCT by config,
   return chosen descriptor + decoded payload + meta `{priors, visits, q_values, search_mode, sims}`.
   Any exception/timeout/`session_capacity`/`unsupported_root` → `None` (policy fallback; search must never
   break gameplay).

## Agent + runner integration

- `models/agent.py`:
  - `RLAgent.__init__`: new optional `search_policy` attribute (default `None`).
  - `_make_move`: after descriptor filtering (:2364) and before `_get_action_from_network` (:2403), if
    `self.search_policy` is set, await `decide(...)`; on success reuse the exact same send/accept path with
    `action_meta["action_source"] = "mcts-search"`, `sampled_from_policy = False`,
    `exclude_from_rollout = True`, and attach `action_meta["mcts"] = {priors, visits, chosen_index}`.
  - `play_game` rollout-queue site (:2116-2139): skip queueing any step whose meta has
    `exclude_from_rollout` — guards the PPO on-policy assumption regardless of who wires search in.
- `training/v2_benchmark.py`: `_frozen_neural` (:56) constructs `SearchPolicy` and passes it when
  `ALPHAGO_SEARCH_ENABLED=1`; benchmark reports gain `search_enabled` and aggregate search stats
  (roots searched, fallbacks, mean latency, invalid-sample rate).
- `training/v2_self_play.py`: **no search wiring to learner seats in this phase** (documented in the plan doc;
  Phase 3 decides how search targets enter training).
- `standalone_bot.py` / human-vs paths: optional flag to play with search against humans.

## Validation / rollout order

1. `python -m pytest tests/test_search_*.py test_agent_search_hook.py` in `rl-environment`.
2. TS stack unchanged gate: existing `SearchSimulationService`/`ApiRlSearch` specs still pass.
3. Docker smoke (fixed seeds): alphago stack with search+determinization flags on, run one `v2_benchmark`
   pass teacher-screen seeds with `ALPHAGO_SEARCH_ENABLED=1`; acceptance: 100% game completion, zero
   policy-rejection regressions, ≥80% of eligible roots searched, mean replay-batch latency logged (feeds the
   100 inputs/s hardware gate from `aplhago-mcts.md`), record results in the reliability table.
4. Phase A→B switch only after smoke: PUCT behind `ALPHAGO_SEARCH_MODE=lookahead|puct` (default `lookahead`).
5. Benchmark A/B (Phase 2 acceptance, per user's plan): identical seeds/seats/weights — champion+policy vs
   champion+search; improvement must come from search, not training. Run after the 10k exact-shadow gate
   note is satisfied or explicitly waived by the user for determinization.

## Key risks

- Determinization still gated off by default and the 10k-input exact-shadow soak is at 715/10000
  (`aplhago-mcts.md:38`); search cannot roll out opponents until `RL_SEARCH_DETERMINIZATION_ENABLED=1`. Plan
  treats enabling it as an explicit user opt-in flag, and Phase-A code paths work in exact mode for
  root-only micro-continuations so smoke can partially run early.
- Replaying full paths from root per rollout step is O(depth²) server work; if the throughput gate fails,
  reduce `simulations_per_move` before touching the TS service (batching, not new endpoints, is the lever).
- Cached continuation paths can become illegal under a new determinization; v1 handles it by truncating that
  simulation — quantify the invalid-sample rate in benchmark reports before Phase B tuning.
